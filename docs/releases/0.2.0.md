# Fidelis Memory 0.2.0 — safer local service startup and installation

## Why this release

Fidelis 0.2.0 makes local service startup safer around existing installs and
lets protocol and health inspection succeed before a local Ollama store is
available.

## Who it is for

This release supports the existing local-first macOS and Linux path for Codex,
Claude Code, GitHub Copilot CLI, Gemini CLI, OpenClaw, and local applications.
Review the [user-fit matrix](../user-fit.md) for prerequisites and explicit
non-fits; Fidelis remains a local, single-machine service rather than a hosted
or managed multi-user offering.

## Install or upgrade

```bash
python3 -m pip install --upgrade "fidelis-memory==0.2.0"
```

Gemini users can install the matching extension after the `v0.2.0` tag exists:

```bash
gemini extensions install https://github.com/hermes-labs-ai/fidelis --ref=v0.2.0
```

## What changed

- `fidelis-server` binds and serves health checks without reachable Ollama;
  memory-backed requests stay unavailable until the local store can load.
- `fidelis init` detects existing service-label and port collisions before
  changing a service, preserves existing environment settings on re-init, and
  offers explicit alternatives for intentional coexistence.
- `FIDELIS_PORT` applies to both the server and MCP client.
- The repository includes a portable Claude plugin root pinned to this release.

## Evidence and known limits

The release PR validates version parity, the no-Ollama server and MCP smoke
paths, collision behavior, and plugin metadata. Ollama and the local embedding
model remain required for retrieval and ingestion. The package does not claim
publication to third-party registries, marketplaces, or archives until each
publisher verifies that service separately.

See the [README limitations](../../README.md#known-limitations-v020) and the
[release procedure](../RELEASING.md) before publishing.
